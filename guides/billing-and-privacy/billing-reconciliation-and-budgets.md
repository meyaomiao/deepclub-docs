# 费用核对与成本核算实战：按量计费、Token 估算与预算控制

使用 **[深云 DeepClub](https://deepclub.net)** 时没有月费捆绑：文本模型按**每百万 Token（输入 / 输出 / 缓存）**计费，图片与视频模型按**每次成功生成**计费（以 [https://deepclub.net/pricing](https://deepclub.net/pricing) 实时公布为准）。

为了方便工程团队和个人开发者把账算清楚，本文整理一套从**单次估算 → 多模型分层 → 控制台对账**的标准方法。

---

## 一、文本、图片、视频三类计费单位如何换算？

### 1. 文本模型（`每百万 Token`）

公式：`单次费用 = (输入Token × 输入单价 + 缓存读Token × 缓存读单价 + 缓存写Token × 缓存写单价 + 输出Token × 输出单价) / 1,000,000`

**直观例子（中文开发/问答经验换算：1 个汉字大约 1.3~2 个 Token，英文约 0.75 词/Token）**：
- 若用 **`gpt-6-luna`**（输入 ¥0.12 / 输出 ¥0.6 每百万 Token）处理 2,000 字输入（约 3,000 Token）+ 生成 800 Token 回复：
  - `3,000 × 0.12 / 1e6 + 800 × 0.6 / 1e6 = ¥0.00036 + ¥0.00048 = ¥0.00084`（不到 1 厘钱）。
- 若用 **`claude-sonnet-5-5`**（输入 ¥1 / 输出 ¥5 每百万 Token）处理一轮 **20,000 Token 命中缓存读（¥0.1/M）+ 1,000 新输入 + 1,000 输出**：
  - `(20,000 × 0.1 + 1,000 × 1 + 1,000 × 5) / 1e6 = ¥0.008`（约 8 厘钱）。
- 若不拆分场景直接用超旗舰模型处理所有清洗任务（如每百万输出 ¥60~¥92），单次成本会差出 **50~100 倍**。

### 2. 图片模型（`每次调用 / 每张图`）

- 每次成功生成或参考图编辑算 1 次（建议请求时保持 **`n=1`**，并在支持 1K/2K/4K 的型号中结合实际清晰度需求选择 `size`）。
- 例如电商批量草图先用 ¥0.16~¥0.24 档位筛选构图，定稿才切换高规格出图。

### 3. 视频模型（`每次调用 / 每个视频`）

- 按成功生成的视频任务数计费（如 `Seedance-2.0-Mini` ¥1.5 起、`MiniMax-H3` ¥2 起、`Seedance-2.0-Fast` ¥2.5 起），与你轮询 `GET /v1/videos/{task_id}` 的查询次数无关。
- **防重复扣费铁律**：`POST /v1/videos` 收到 `id` 后立刻落盘；若客户端断网，重启后只做 `GET /v1/videos/{id}` 查状态与下载，**不要在未查旧任务状态前重复提交新任务**。

## 二、80/20 模型路由：在保证质量的前提下直接省掉 60%~80% 费用

| 任务分层 | 占比（经验值） | 推荐路由模型 |
|---|---|---|
| **L1：翻译、标签分类、日志提取、意图识别** | 60%+ | `gpt-6-luna`、`gemini-4-hydrogen`、`glm-5.3-flash` |
| **L2：日常编码、RAG 问答、单元测试、PR 审查** | 30% | `claude-sonnet-5-5`、`gpt-6.1-sol`、`deepseek-v4.1-flash`、`gemini-4-argon` |
| **L3：复杂系统架构、疑难并发定位、长合同终审** | <10% | `claude-opus-5-5`、`claude-fable-5-2`、`gpt-6-astra`、`glm-5.3`、`kimi-k3` |

## 三、三步对账流程

1. **请求前核对公开接口**：程序或脚本可通过免鉴权接口 `GET https://deepclub.net/api/sale_models` 拉取实时在售模型单价、单位、端点与规格参数，避免文档过时。
2. **代码侧记录消耗**：每次非流式请求响应中的 `usage` 字段（或流式末尾的 usage event）记录日志；Anthropic Messages 的缓存读/写位于 `usage.cache_read_input_tokens` 与 `usage.cache_creation_input_tokens`。
3. **控制台逐笔核对**：打开 [深云 DeepClub](https://deepclub.net) → **使用日志**，筛选对应 API Key（子 Key），即可核对每一笔真实模型、Token 组成、耗时和扣费金额。
